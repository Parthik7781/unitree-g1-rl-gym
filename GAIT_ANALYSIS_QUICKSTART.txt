## Results Status Guide

### ✓ PASS - Gait is Correct
- Phase shift: ~180° (legs alternate perfectly)
- Symmetry: >85% (balanced walking)
- **Action**: No adjustments needed

### ⚠ PARTIAL - Phase Issue
- Phase shift: >30° error
- Symmetry: Good
- **Cause**: Leg coordination problem
- **Fix**: Check motor synchronization, sensor phase offsets

### ⚠ PARTIAL - Symmetry Issue
- Phase shift: Correct
- Symmetry: <85% (unbalanced)
- **Cause**: One leg weaker or longer
- **Fix**: Check leg length, motor strength, weight distribution

### ✗ FAIL - Multiple Issues
- Both phase and symmetry problems
- **Action**: Perform hardware diagnostics

## Phase Shift Calculation (Technical)

**What is it?**
The time delay between when left leg reaches peak and right leg reaches peak.

**Expected for Normal Walking:**
- 180° (half gait cycle)
- For 1-second cycle: 0.5 seconds delay

**How it's calculated:**
1. Use Hilbert transform on gyroscope data
2. Extract instantaneous phase
3. Calculate mean phase difference
4. Convert to degrees: (phase_rad / 2π) × 360°

**Formula:**
```
phase_shift_deg = mean(φ_right - φ_left) × 180/π

For correct gait:
  180° ± 30° acceptable
```

**Why Hilbert Transform?**
- Better than cross-correlation for periodic signals
- Directly measures phase, not just similarity
- Robust to noise and amplitude changes
- Works with complex motion patterns

## Data Format (CSV Files)

Each CSV contains:
```
timestamp,sample_num,ax,ay,az,gx,gy,gz,roll,pitch,yaw

Example:
0.0,      0,  0.078,-0.084, 5.31, -0.047, -0.098, 0.011, 0.1, 0.0, 0.0
0.01,     1,  0.311, 0.058, 5.26,  0.074,  0.088, 0.040, 0.12, 0.006, 0.001
...
```

**Columns:**
- `timestamp`: Time in seconds (0.0, 0.01, 0.02, ...)
- `sample_num`: Sequential number (0, 1, 2, ...)
- `ax, ay, az`: Acceleration (m/s²) in 3 axes
- `gx, gy, gz`: Angular velocity (rad/s) in 3 axes
- `roll, pitch, yaw`: Orientation (radians) in 3 axes

**Axes Convention:**
- `ax`: Forward/backward (anterior-posterior)
- `ay`: Left/right (medial-lateral)
- `az`: Up/down (vertical)

## Preprocessing Applied

Data processing pipeline:

```
Raw IMU Data
    ↓
Low-pass Filter (Gaussian, σ=2)
    ↓
Integration: a → v
    ↓
High-pass Filter (0.5 Hz cutoff)
    ↓
Integration: v → x
    ↓
Linear Detrending
    ↓
Foot Trajectory (clean)
```

**Why this process?**
- Reduces noise from sensors
- Removes gravity drift during integration
- Preserves motion information
- Results in smooth, clean trajectories

## Troubleshooting

### Issue: "Phase shift shows 0°"
- Sensors may be out of sync
- Check hardware connection
- Verify sensor orientation

### Issue: "Plots look wrong"
- Check sensor calibration
- Verify data range (no clipping)
- Check for sensor failures

### Issue: "Symmetry very low"
- One leg may be weaker
- Check alignment and calibration
- Verify motor strength matching

### Issue: "All values are NaN"
- Sensor communication failure
- Check USB/network connection
- Restart system

## Customization

### Change gait cycle duration:
Edit `validate_gait.py`:
```python
success = system.run(
    duration_per_cycle=1.0,    # seconds (default)
    num_gait_cycles=3          # cycles (default)
)
```

### Change phase tolerance:
Edit `gait_analysis.py`, line ~320:
```python
is_correct_phase = bool(phase_error < 30.0)  # degrees
```

### Change symmetry threshold:
Edit `gait_analysis.py`, line ~310:
```python
is_symmetric = bool(overall_symmetry > 0.85)  # >85%
```
